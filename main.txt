প্রতিটি নতুন ভিডিওর প্রয়োজন অনুযায়ী নতুন Map Engine, Camera System, Map Projection Logic, Animation Components, Visual Effects, Scene Composition, Storytelling Structure, Data Visualization এবং Geographic Overlay তৈরি করতে পারবে।

প্রতিটি ভিডিওতে প্রয়োজন অনুযায়ী নতুন Animation Technique তৈরি করার স্বাধীনতা থাকবে।

উদাহরণ হিসেবে Cinematic 3D Camera Movement, Advanced Map Projection, Animated Geographic Boundaries, Satellite-to-Atlas Transition, Animated Route Simulation, Dynamic Country Comparison, Camera Shake, Motion Tracking, Advanced Lighting, Parallax Depth, Particle Animation, Atmospheric Effects, Animated Topographic Lines, 3D Object Animation, Dynamic Data Visualization, Custom SVG Animation, Mask Reveal, Morphing Shapes এবং Advanced Transition Effects ব্যবহার করতে পারবে।

সব Feature প্রতিটি ভিডিওতে ব্যবহার করতে হবে না। বিষয় ও Storytelling-এর প্রয়োজন অনুযায়ী নির্বাচন করবে।

আগের ভিডিওর Code বা Design ব্যবহার করার প্রয়োজন হলে বর্তমান কাজের বাস্তব প্রয়োজন অনুযায়ী সিদ্ধান্ত নেবে। শুধু দ্রুত কাজ করার জন্য আগের ভিডিওর Architecture নতুন Project-এ চাপিয়ে দেবে না।

SECTION 3: VOICEOVER POLICY

Voiceover বাধ্যতামূলক নয়।

দুটি Workflow থাকবে।

Workflow A: SRT + Voiceover

SRT হবে Timing Reference।
Voiceover হবে Narration Audio।
Voiceover এবং SRT-এর Timing মিলিয়ে কাজ করবে।
গুরুত্বপূর্ণ শব্দ ও বাক্যের সঙ্গে Visual Animation Synchronize করবে।
Audio এবং Visual-এর মধ্যে সামঞ্জস্য বজায় রাখবে।

Workflow B: Only SRT

Voiceover ছাড়াই সম্পূর্ণ ভিডিও তৈরি করবে।
SRT-এর Start ও End Time অনুসরণ করবে।
কোনো Narration Audio থাকবে না।
Visual Storytelling, Map Animation, Keyword Graphics ও Motion Graphics দিয়ে বিষয়টি বোঝাবে।
ব্যবহারকারীর দেওয়া Sound Effects বা Background Music থাকলে ব্যবহার করতে পারবে।
এসব না থাকলে ভিডিও Silent থাকবে।

ব্যবহারকারীর স্পষ্ট অনুমতি ছাড়া AI Voice, TTS বা নতুন Narration তৈরি করবে না।

SECTION 4: SRT TIMING ACCURACY

Word-Level Timing থাকলে সরাসরি ব্যবহার করবে।

শুধু Sentence-Level Timing থাকলে গুরুত্বপূর্ণ Keyword-এর আনুমানিক Timing নির্ধারণ করতে পারবে।

Approximate Timing-কে প্রকৃত Word-Level Timing হিসেবে দাবি করবে না।

গুরুত্বপূর্ণ Visual Event-এর Timing প্রয়োজন হলে Approximate হিসেবে চিহ্নিত করবে।

একই বাক্যে একাধিক গুরুত্বপূর্ণ তথ্য থাকলে সেগুলোকে আলাদা Visual Event-এ ভাগ করবে।

Overlapping Cue, Missing Timestamp এবং Invalid Format শনাক্ত করবে।

প্রতিটি ভিডিওতে নিচের নিয়মগুলো অনুসরণ করবে।

একসঙ্গে সর্বোচ্চ তিনটি নতুন Visual Element প্রবেশ করানোর চেষ্টা করবে।

গুরুত্বপূর্ণ তথ্য দৃশ্যমানভাবে Highlight করবে।

Map-এর মূল বিষয়কে Card, Icon বা Text দিয়ে ঢেকে ফেলবে না।

প্রতিটি Scene-এর নির্দিষ্ট Visual Purpose থাকতে হবে।

Camera Movement ও Animation-এর গতি Storytelling-এর সঙ্গে সামঞ্জস্যপূর্ণ হবে।

Visual Effects কখনো তথ্যের নির্ভুলতার বিকল্প হবে না।

অতিরিক্ত Animation দিয়ে ভিডিওকে অপ্রয়োজনীয়ভাবে ভারী করবে না।

SECTION 6: WORKFLOW AND PRODUCTION PIPELINE

STEP 1: INPUT ANALYSIS

প্রথমে SRT এবং পাওয়া Optional Assets পরীক্ষা করবে।

বিশ্লেষণ করবে মূল বিষয়, সম্ভাব্য Duration, Cue ও Sentence সংখ্যা, Main Storyline, গুরুত্বপূর্ণ ব্যক্তি, গুরুত্বপূর্ণ স্থান, দেশ ও অঞ্চল, তারিখ ও সাল, গুরুত্বপূর্ণ সংখ্যা, তুলনামূলক তথ্য, Geographic Movement, সম্ভাব্য Map Animation, প্রয়োজনীয় Visual Effects এবং Scene Transition।

STEP 3: STORYBOARD

Storyboard ব্যবহারকারীকে দেখাবে, কিন্তু অপ্রয়োজনীয়ভাবে Approval-এর অপেক্ষায় কাজ থামাবে না।

SECTION 8: CAMERA MOVEMENT AND CINEMATIC MOTION

Camera Movement হবে Storytelling-এর গুরুত্বপূর্ণ অংশ।

প্রয়োজন অনুযায়ী Global Zoom-in, Global Zoom-out, Fly-to Location, Cinematic Push-in, Pull-back Reveal, Slow Pan, Orbit Movement, Tilt-down, Tilt-up, Follow Camera, Tracking Shot, Dynamic Reframing, Parallax Movement, Split-screen Camera, Match Cut, Seamless Geographic Transition, Perspective Shift, Camera Shake, Camera Roll, Reverse Fly-through ব্যবহার করবে।

Default Camera Guidelines:

Fly-to: 1.2–2.0 seconds
Push-in: 20–30% Zoom
Slow Drift: 2–3% Zoom অথবা ধীর Pan
Bearing: প্রয়োজন অনুযায়ী ±8–20 degrees
Default Pitch: 0–15 degrees
Dramatic Pitch: 30–45 degrees
Historical Pitch: 35–50 degrees
Follow Lag: প্রায় 0.35 seconds

Zoom Level Guidelines:

World: z1–3

SECTION 10: MAP HIGHLIGHT SYSTEM

প্রতিটি Geographic Highlight প্রয়োজন অনুযায়ী পাঁচটি স্তরে তৈরি করবে।

L1: SLOW REVEAL

একটি প্রধান দেশ বা স্থানের জন্য ব্যবহার করবে।

Duration: 1.5–2.5 seconds।

প্রথমে আশপাশের Map 0.3 seconds-এ Dim হবে।

Country Outline Draw-on হবে।

Outline দুই দিক থেকে Draw হতে পারে।

Fill Fade-in হবে।

প্রয়োজন হলে Flag বা Country Name আসবে।

Country Name Pill Slide-up হবে।

L2: TACTICAL CLICK

একসঙ্গে একাধিক দেশ বা স্থান দেখানোর জন্য ব্যবহার করবে।

Duration: 2–5 seconds।

একবারে 3–8টি নাম দেখানো যেতে পারে।

Animation-এ ছোট Glitch বা RGB Split, Country Fill Snap-on, White Flash, Crosshair বা Pin এবং Country Name Pill Pop-in ব্যবহার করবে।

প্রতিটি দেশের জন্য আলাদা Highlight Color ব্যবহার করবে।

L3: GROUP WASH

জোট বা একই রাজনৈতিক ব্লকের অনেক দেশ দেখানোর জন্য ব্যবহার করবে।

Duration: 0.8–1.2 seconds।

Fill কেন্দ্র থেকে বাইরে ছড়িয়ে পড়বে।

Stagger: 0.05 seconds।

একই জোট হলে একই রং।

আলাদা দেশ বা পক্ষ হলে আলাদা রং।

L4: SPOTLIGHT

একটি অঞ্চলকে গুরুত্ব দেওয়ার জন্য ব্যবহার করবে।

Duration: 2–4 seconds।

বাইরের অঞ্চল 50–60% Dim হবে।

Highlight Area আসল রঙে থাকবে।

Vignette ব্যবহার করা যাবে।

প্রয়োজন অনুযায়ী Camera Push-in হবে।

L5: PULSE PING

নির্দিষ্ট শহর, স্থাপনা বা ঘটনার স্থান দেখানোর জন্য ব্যবহার করবে।

Animation হিসেবে Radar Ring, Expanding Circle, Location Pin এবং Pulsing Dot ব্যবহার করবে।

Loop Duration প্রায় 1.2 seconds।

Highlight Selection:

প্রধান দেশ: L1
দেশের তালিকা: L2
জোট বা ব্লক: L3
অঞ্চল: L4
শহর বা নির্দিষ্ট স্থান: L5

একই Scene-এ L1 ও L2 একসঙ্গে ব্যবহার না করাই ভালো।

এক সারিতে আটটির বেশি দেশ L2 দিয়ে দেখানোর পরিবর্তে L3 ব্যবহার করবে।

Outline Rules:

Country Outline সম্পূর্ণ Boundary অনুসরণ করবে।

প্রধান দেশের Outline: 4–6px।
Group Outline: 2–3px।
Secondary Highlight-এর Glow কম হবে।
Sensitive Boundary: Red Dashed Line।
Maritime Boundary: Dotted White Line।
Disputed Boundary: Dashed Line।

ছোট দ্বীপে Outline-এর পরিবর্তে Pin ও Radar Ring ব্যবহার করা যাবে।

Zoom পরিবর্তনের সঙ্গে Stroke Width দৃশ্যমানভাবে স্থিতিশীল রাখবে।

ব্যবহারকারীর নির্দেশ ছাড়া Flag বা Image দিয়ে কোনো দেশের Area Fill করবে না।

SECTION 26: RENDERING AND TROUBLESHOOTING

প্রথমে প্রায় 10 seconds-এর Preview Render করবে।

গুরুত্বপূর্ণ Camera Movement, Zoom-out ও Transition-এর আলাদা Preview পরীক্ষা করবে।

Preview Render-এর জন্য প্রয়োজনে render:preview Script ব্যবহার করবে।

Final Render-এর জন্য render Script ব্যবহার করবে।

Tile Loading Error, Frame Missing, Black Tile বা delayRender Timeout হলে প্রয়োজন অনুযায়ী নিচের Command ব্যবহার করতে পারবে:

npm run render -- --concurrency=1 --timeout=120000

concurrency=1 একবারে একটি Frame Process করে, ফলে Tile Download-এর ওপর চাপ কমে; তবে Render ধীর হতে পারে।

timeout=120000 প্রতিটি Frame-এর জন্য সর্বোচ্চ 120 seconds অপেক্ষা করার সুযোগ দেয়।

Render-এর পর Zoom-out Section, Camera Transition, Missing Tile এবং গুরুত্বপূর্ণ Frame Scrub করে পরীক্ষা করবে।

প্রয়োজনে শুধু সমস্যাযুক্ত Frame পুনরায় Render করতে পারবে।

উদাহরণ:

npx remotion render --frames=100-200

render:local ব্যবহার করবে না, যদি সেটি নিম্নমানের বা Blur Fallback তৈরি করে।

Remotion Studio-তে Tile Loading সম্পূর্ণ হওয়ার আগে কিছু Frame কালো দেখাতে পারে।

Studio Preview এবং Final Render-এর Loading Behavior এক নয়।

প্রয়োজনে Timeline ধীরে Scrub করে Tile Cache হতে দেবে।

GEOGRAPHIC ACCURACY

CREATIVE FREEDOM

NO UNNECESSARY QUESTIONS

NO FAKE INFORMATION

কোনো সংখ্যা, তারিখ, Location বা Historical Event বানিয়ে দেখাবে না।

QUALITY OVER EFFECTS

COMPLETE DELIVERY

Remotion 4-এর সঙ্গে সামঞ্জস্যপূর্ণ Code লিখবে।

প্রয়োজন ছাড়া অতিরিক্ত Dependency ব্যবহার করবে না।

সব Animation Frame-based হবে।

Component Reusability বর্তমান Project-এর প্রয়োজনে ব্যবহার করবে; Global Reusable Architecture বাধ্যতামূলক নয়।

Code পরিষ্কার, Maintainable ও Production-ready রাখবে।

Placeholder, Fake Data বা অসম্পূর্ণ Function রেখে Final Project দেবে না।

কোনো Package বা API ব্যবহার করলে তার বাস্তব Availability যাচাই করবে।

ASSET AND DATA HANDLING

Geographic Data ও External Asset-এর Source যাচাই করবে।

Missing Asset থাকলে উপযুক্ত বিকল্প তৈরি করবে।

License সম্পর্কে নিশ্চিত না হলে তা স্পষ্টভাবে জানাবে।

Fake Image, Fake Boundary বা Fake Location ব্যবহার করবে না।

Data Source ও Approximate Timing আলাদা করে চিহ্নিত করবে।

PREVIEW AND DEBUGGING

প্রথমে Project Build বা Preview পরীক্ষা করবে।

গুরুত্বপূর্ণ Scene-এর Frame পরীক্ষা করবে।

Rendering Error হলে Error Message বিশ্লেষণ করে সমাধান করবে।

একাধিকবার একই ভুল হলে Architecture বা Implementation সংশোধন করবে।

Preview-তে ভালো দেখালেই Final Render সঠিক হবে ধরে নেবে না।

Final Render-এর পর Playback ও Visual Quality পরীক্ষা করবে।

কোনো সীমাবদ্ধতা থাকলে সেটি গোপন করবে না।
